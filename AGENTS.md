# Elecalculate

Elecalculate is a German educational electronics reference and calculator site
by Jana Ruch. It is being sunset as a content project. Preserve the existing
calculators and explanations rather than replacing them with a new demo.

## Architecture

- Bun 1.4.4, TypeScript 7, React 19, TanStack Start and Router, Query, Form,
  Tailwind 4, Drizzle 1 RC, PGlite in a worker, local KaTeX and Three.js.
- `src/routes/` owns routing, metadata, and validated search parameters.
  `src/routeTree.gen.ts` is generated by Start, never edited manually.
- `src/pages/` contains native React page components. `src/calculations/`
  contains mount-scoped calculation modules ported from the original site.
  Numerical calculations now delegate to independently tested TypeScript domain
  solvers in `src/lib/`. Historical JavaScript remains for presentation and
  simulation orchestration; never restore faulty arithmetic from the fixtures.
- `src/lib/controller.ts` scopes DOM queries, listeners, animation frames and
  timers to a mounted page. `use-calculator.ts` disposes them on navigation,
  validates numeric input, and restores notebook entries.
- Solutions generated by existing algorithms pass through `setHTML` and
  DOMPurify. Never inject input directly into untrusted HTML or use eval.
- `src/lib/equations.ts` supplies finite, domain and consistency checks for the
  typed basic, OPV, passive and AC solvers. Internal values retain full precision,
  including very small SI quantities. Test forward/inverse identities and physical
  limits independently; matching historical code is not evidence of correctness.
- `scripts/calculation-patches.ts` wires reviewed domain adapters and simulator
  fixes into the reproducible port. Update it when generated orchestration changes.
- `data-result-key` and `data-result-value` expose unrounded SI results for browser
  verification. Human labels retain the original engineering-unit conventions.
- Notebook queries and mutations use Query; the save form uses Form. Drizzle
  owns the PostgreSQL schema. PGlite runs in a worker and persists to IndexedDB,
  sharing one database across tabs. Local queries/mutations require
  `networkMode: "always"`; connectivity changes must never pause local storage.
  Data-free cross-tab invalidation runs only after committed writes.
- Snapshots preserve modes, active toggles and optional typed controller state via
  `calculator-state.ts`. Replay colour selectors; do not restore readonly derived
  outputs or scrape rendered formulas. Keep explicit generated control IDs stable.
  Busy simulations refuse capture until the accepted operation completes.
- Saved-entry loading is an explicit `data-restoring`/inert state. It must finish
  logically before editing or public capture is permitted; transactional restore
  alone may bypass its own root loading flag. Keep user resume edits ahead of
  loading the original `?notiz` record after an update.
- Qubit mathematical DOM updates precede coalesced GPU drawing. Idle ornament
  rendering is budgeted and yields during notebook work; active gestures remain
  responsive. Do not put synchronous GPU work ahead of restored results.
- Removed entries remain recoverable after reload. Worker startup waits for real
  readiness, loads bundled WASM/data explicitly, and has bounded error/retry paths.
  No calculator data is sent to a server.
- Drizzle's pg-proxy driver talks to the PGlite worker query interface. Do not
  cast the worker to a full PGlite instance or import filesystem migration APIs
  into the browser. Bundle reviewed SQL migrations through `src/db/migrations.ts`.

## Source migration and provenance

- `migration/source/` preserves development commit
  `79be0089b5d6a1b05f9246bb246326abc21d69f1`, including the Qubit page missing
  from the older main branch. These files are build/test inputs, never served.
- `scripts/migrate-source.ts` ports the original markup to native JSX event
  bindings and scopes the calculation modules. It normalizes broken source
  markup, bundles external dependencies, and applies documented corrections.
- Generated page/calculation files are ordinary maintainable source. If you
  change their structure, update the migration generator too, or retire the
  generator explicitly once hand migration supersedes it.
- `migration/unmerged-el52/` preserves unmerged solver work. Do not silently
  replace newer development pages with that older branch's entire files.
- `migration/coverage.json` records the full page/input/event inventory.
- FET and active-filter pages were unfinished in the original. Do not invent
  implemented functionality for them.

## Commands and verification

- `bun install --frozen-lockfile`
- `bun run dev` serves only 127.0.0.1:4317 and refuses occupied ports.
- `bun run migrate:source` regenerates the port and formats generated files.
- `bun run test` runs SI, validation, and dependency-solver tests.
- `bun run build` prerenders all routes and generates old-URL redirects,
  offline assets, CNAME, sitemap and version.json into `dist/client`.
- `bun run typecheck`
- `bun run start` serves the actual static build on 127.0.0.1:4317.
- `bun run test:e2e` checks native routes, calculator/source parity, independent
  independent numerical references, inverse/zero/boundary cases, notebook
  persistence, multi-tab access, offline
  operation, desktop and mobile rendering, and original inbound URLs.
- `bun run test:webkit` runs the complete suite on actual WebKit desktop/mobile
  profiles, isolated on port4321 and `test-results-webkit`. Chromium uses4317.
- `bun run verify` runs all required checks, including both browser engines.
  Install runtimes with `bunx playwright install chromium webkit` when needed.
- Do not run multiple Playwright commands against the same output directory
  concurrently; they remove each other's traces.

## Design and deployment

- Preserve the original black HTML-site appearance: black page backgrounds,
  white text, compact gray fixed header, hamburger category menu, horizontally
  scrollable topic links and centered calculator content. Refresh the existing
  UI gently; do not replace it with a sidebar dashboard or light document theme.
- Use decorative SVG icons with `currentColor`, never emoji or platform-dependent
  Unicode glyphs as navigation icons. Keep accessible names on their controls.
- No marketing dashboard, slogan hero, numbered instrument cards, neon badge
  decoration, em dashes or en dashes. The UI is a technical reference organized
  around the existing topics, source diagrams, forms, tables and worked solutions.
- Preserve the educational SI-variable colour meanings. Keep readable contrast,
  native keyboard controls, reduced-motion styles and mobile layouts.
- Only `main` and `gh-pages` remain active branches. Retired heads are preserved
  through annotated sunset tags and `migration/branch-snapshots.json`.
- `main` contains source. `gh-pages` contains only the verified static build.
  `dist/server` is a build-time prerender dependency, not the deployed runtime.
- GitHub Pages uses the existing custom domain elecalculate.com. Preserve CNAME.
- The CI workflow verifies before publishing, then explicitly requests a Pages
  build. There are no alternate branch previews or force-pushed offline branches.
- Offline installation caches the complete build atomically. A waiting update
  requires explicit activation, preserving unsaved calculator inputs and state in
  tab-local session storage. Open note drafts block reload. Never claim success
  merely because an older worker is ready.
- Retain old chunks while another tab uses them. Prune caches only after safe
  generation acknowledgement from all live windows, including WebKit, which can
  omit navigation FetchEvents. Build identity is deterministic in Vite/HTML/SW.
- `/aktualisieren.html` is a standalone recovery path for older cache-first
  versions. It must not delete IndexedDB or user records.
- Offline use requires HTTPS or localhost, not file://. Unsupported storage or
  browser capabilities must fail promptly with actionable UI, never spin forever.
